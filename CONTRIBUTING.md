# Contributing to viberoom

Thank you for taking the time. Here is how contributions work in this project, so that nobody
spends an evening on a pull request that cannot be merged.

## Questions, ideas, bugs

- A question ("how do I ...?") goes to [Discussions → Q&A](https://github.com/todor-rusev/viberoom/discussions/categories/q-a).
- An idea goes to [Discussions → Ideas](https://github.com/todor-rusev/viberoom/discussions/categories/ideas).
  Say what you want to do in the room and where viberoom gets in the way; the design comes from
  that, not from a patch.
- A bug goes to [Issues](https://github.com/todor-rusev/viberoom/issues/new/choose); the form asks
  for what a fix needs.

## Pull requests

viberoom has one author. Pull requests are read with care and used, but they are not merged as they
are: the change is written into the project by the author, in the project's own design, and the
person who proposed it is credited in the commit that ships it (a `Suggested-by:` line with their
name) and in the release notes.

This keeps the code with a single copyright holder and a single style, which is what lets the
project be restructured or relicensed later without hunting for permissions. If that ever changes,
a contributor licence agreement will come first, and this file will say so.

So, before you write code:

1. Open an issue or a discussion that describes the problem and, if you like, the fix you have in mind.
2. Wait for a reply; most proposals get one within a few days.
3. If you still want to send a pull request, keep it small and focused: a worked example of the
   proposal, not the final code.

A pull request that adds a coding agent (a recipe) should say on which of the three platforms
viberoom supports (Windows, macOS, Linux) it was run. A recipe nobody here can verify is not shipped.

## Welcome without asking

- Bug reports with a way to reproduce them.
- Screenshots of what looks wrong.
- Notes on the documentation: a sentence that misled you is a bug too.

## Licence

viberoom is AGPL-3.0-or-later. By proposing a change you agree that, when the author writes it into
the project, the resulting code is the author's under that licence, and that your name may be used
to credit the idea.
